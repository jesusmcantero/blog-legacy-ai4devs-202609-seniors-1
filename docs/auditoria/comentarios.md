# Auditoría — feature COMENTARIOS

**Alcance:** crear, editar, borrar y listar comentarios en sus tres capas: API (`backend/start/routes.ts`),
base de datos (`backend/database/migrations/1769000000005_create_comentarios_table.ts`, `backend/database/schema.ts`,
`backend/database/seeders/blog_seeder.ts`) y web (`frontend/src/componentes/Comentarios.jsx`, `DetallePost.jsx`,
`ListaPosts.jsx`, `PostsRelacionados.jsx`). Más los tests (`backend/tests/functional/comentarios.spec.ts`,
`backend/tests/bootstrap.ts`). Posts, autores, categorías y etiquetas quedan fuera salvo donde pasan por comentarios
(recuento en listados y relacionados, comentarios embebidos en el detalle).

**Método:**

1. Lectura del código entero de las tres capas.
2. `make test` en el repo: **verde, `Tests 1 passed (1)`**. Es el único test que existe.
3. Consultas de solo lectura a la base real (`sqlite3 -readonly backend/tmp/db.sqlite3`): esquema y filas de `comentarios`.
4. Verificación en ejecución sobre una **copia** del backend fuera del repo (scratchpad, con su propia copia de la base):
 16 pruebas Japa que registran lo que la API hace hoy, con y sin transacción global. El repo y su base no se han
 tocado (mismo md5 de la base antes y después).
5. Revisión: abrí el archivo y la línea de cada fila, y relancé las 16 pruebas de verificación sobre la copia
 resembrada. Las casillas que corregí llevan la marca *(Corregido al revisar: …)*.

La columna **Comprobación** dice si la fila se ha visto en ejecución o solo leyendo código.

**Orden de la tabla = prioridad.** Orden de ataque que sale de las dependencias:
tests de caracterización (H28–H32) → H1 → H2/H3 → H8 → H6/H7 → H5 → el resto.

Rutas relativas a la raíz del repo; `routes.ts` = `backend/start/routes.ts`; «migración» =
`backend/database/migrations/1769000000005_create_comentarios_table.ts`.
